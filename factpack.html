Read this before you publish a number

Check any figure with us before it goes out, including figures you find on our own site. Memory-benchmark numbers across this industry are actively disputed, and vendors have publicly accused each other of judge-shopping and inflated reporting. A wrong number costs you more than no number.

If a figure is not on this page, it is not public yet. We run work that has not been published. Please do not reach for it.

The ranking claim, handled carefully

This is the single easiest thing to get wrong, so it gets its own section.

Say this

  • "#2 on the community leaderboard, behind agentmemory V4 at 96.2% and tied with Chronos by PwC at 95.6%"
  • "the only file-based system in the top tier"
  • "95.6% on LongMemEval, self-reported, as are all entries on that board"

Not this

  • "officially ranked #2 on LongMemEval"
  • "#2 on the LongMemEval leaderboard" with no qualifier
  • Any phrasing implying a governing body verified the placement
Why the distinction is real

The LongMemEval authors do not publish a leaderboard. The ranking comes from a community-maintained comparison of numbers that each system reports about itself. Judges and generator models vary between entries, which means the ordering is informative but not authoritative. Our own published post carries this caveat verbatim, and anything written about us should carry it too:

"Self-reported results. No official leaderboard exists. Judges and generator models vary across entries."

The scorer story, if you want the honest version

The plugin run first scored 88.1%. A diagnostic found that 32 of 36 temporal-reasoning misses were the scorer failing, not the memory failing: LongMemEval encodes two acceptable answers in one gold string, and our v2 scorer read it as a single answer. The v3 scorer splits that format. The model's outputs never changed. We publish both numbers and the scorer source so anyone can check. This is a good detail to write about, and it is on the record precisely so nobody has to take our word for it.

Independent third-party benchmark

Run by an outside beta tester on his own machine against four memory engines, not by us. He publishes it at agent-bench.xyz with no affiliation to any system tested. 500 companies, 1,500 people, 365 simulated days, 191k records, 350 questions across 7 categories. Retrieval was isolated from the model, then Claude Sonnet 4.6 answered from the retrieved context.

Sibyl averaged 2.10 context rows and 227.76 tokens per query with zero write-time LLM calls. Hindsight read roughly 11,892 tokens per query, about 52 times more, and answered worse. Mnemosyne's 55 answered is mostly the 50 negative-trap questions, which require refusing rather than remembering.

How to frame this one

Call it an independent beta-tester run. These are the tester's own runs on each system, not figures the vendors reported about themselves, and not a Sibyl-published benchmark. Do not merge these numbers with the LongMemEval scores above; they are different tests measuring different things.

Our one consistent weakness is the "segment" category, current relational state buried in long history, where we scored 41 of 48. The fact is in memory and exact recall finds it; keyword ranking lets journal rows crowd out the entity row. It is a ranking problem, we have said so publicly, and it is the specification for the graph-native tier in development. No timeline.
